# قاعدة بيانات Opera

تستخدم نسخة الموقع الحالية PostgreSQL عبر `DATABASE_URL` الذي يوفّره مشروع Replit. الخادم لا ينفّذ DDL أو يطبّق ترحيلات عند بدء التشغيل.

## المخطط

- ملف المصدر: `database/schema.sql`.
- يُطبّق المخطط على قاعدة التطوير في Replit، ويدير Replit نقل تغييرات المخطط للإنتاج عند النشر.
- `npm run db:init` يفحص الاتصال وعدد الجداول والعروض؛ لا ينشئ أو يعدّل الجداول.
- `npm run db:test` يفحص اتصال PostgreSQL، معاملات `$1`، المخطط، عروض الصلاحيات، والتراجع عن المعاملة.

## نقل بيانات SQLite

تم نقل بيانات ملف `opera.db` المرفق إلى قاعدة التطوير. تحتوي أداة الاستيراد `scripts/import-sqlite.ts` على مسار استيراد لمرة واحدة:

```sh
SQLITE_IMPORT_FILE=/path/to/opera.db npm run db:import-sqlite
```

ترفض الأداة الدمج إذا كان جدول `users` في PostgreSQL يحتوي بيانات، وتنسخ الجداول العادية مع تأجيل قيود المفاتيح الأجنبية داخل معاملة واحدة. لا تُضمّن ملف SQLite أو `.env` في التطبيق.

## نطاق الترحيل

يحتوي `database/schema.sql` على الجداول والفهارس وعرضي الصلاحيات اللذين يحتاجهما تسجيل الدخول. الترحيلات والاختبارات القديمة موجودة في `database/legacy-sqlite-migrations/` و`database/legacy-sqlite-tests/` للرجوع إليها، لكنها لا تعمل في الخادم. لم تُنقل بعد مشغلات SQLite والعروض الأخرى؛ بعض سياسات تسجيل الدخول والجلسات نُقلت إلى طبقة الخادم، لكن ميزات الإدارة والتحليلات المعتمدة على تلك المشغلات تحتاج ترحيلاً منفصلاً.

لا تضف ترحيلاً تلقائياً عند تشغيل التطبيق، ولا تضع مفاتيح أو كلمات مرور في ملفات المشروع.
