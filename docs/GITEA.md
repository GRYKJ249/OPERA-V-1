# Git-Opera

## البنية الحالية

- قاعدة التطبيق النشطة الوحيدة هي `opera_dev` على PostgreSQL. تبقى جداول Opera في مخطط `public`، وجداول Gitea في مخطط `gitea` داخل قاعدة PostgreSQL نفسها.
- PostgreSQL يحفظ بيانات الحسابات وبيانات المستودعات الوصفية. ملفات Git الفعلية تُخزَّن في `/var/lib/opera/gitea/repositories`؛ هذا المجلد مخصص للمستودعات فقط.
- نقطة الدخول إلى Git-Opera هي `/git/`، وتمر عبر جلسة Opera. حساب المالك مدير في Opera وGit-Opera، والتسجيل العام مغلق.
- Gitea لا يستمع للعامة مباشرة؛ Opera يتحقق من جلسة الدخول ويمرر هوية موثوقة إلى Gitea. Git عبر HTTPS يحتاج اعتماد Git أو رمز وصول؛ جلسة المتصفح وحدها لا تصادق أوامر `git`.
- لا تُخزّن محتويات المستودعات في جداول PostgreSQL. جدول Opera `project_repositories` يحتفظ ببيانات الربط بين مشروع Opera ومستودع Gitea.

## مصدر Gitea في المشروع

أُدرج المصدر الرسمي المطابق للنسخة العاملة، Gitea `v28.0.0`، داخل `third_party/gitea` من الوسم `v28.0.0` (commit `b79a3480a1c1adf7463ae3c72ca8fb998581596f`). احتُفظ بملف الترخيص MIT الأصلي. لبناء Gitea من هذا المصدر شغّل `npm run gitea:build`؛ يتطلب ذلك Go 1.27 أو أحدث وNode.js 22 أو أحدث و`make`.

هذا يجعل مصدر Opera ومصدر Gitea ضمن مستودع المشروع نفسه، لكنه لا يحوّل Gitea إلى مكتبة Node أو إلى عملية واحدة: Opera (Node.js) وGitea (Go) يبقيان خدمتين خلفيتين متصلتين. لم يُستبدل البرنامج الثنائي العامل أو يُعاد تشغيل الخدمة بهذا التغيير.

## الحالة

- قاعدة `opera_gitea` وقاعدة المعاينة القديمة أزيلتا من PostgreSQL بعد إعداد المخطط `gitea` داخل `opera_dev`.
- توجد جداول Gitea في مخطط `gitea`، وحساب المالك بصلاحية مدير. المستودعات التي ينشئها المستخدم خاصة؛ لا تُسرد أسماؤها في هذه الوثيقة.
- صفحة الملفات العامة `/pages/storage.html` أزيلت؛ هذا الموقع مخصص لمستودعات Git فقط، وليس لمساحة رفع ملفات عامة أو Nextcloud.
- صفحة Opera الرئيسية تحتفظ برابط Git-Opera الموجود في المشروع. تسجيل الدخول بكلمة المرور والبصمة وOAuth يعود إلى `/git/`.
- رمز API الذي يستخدمه خادم Opera محفوظ في `.env` محليًا بصلاحيات المالك فقط، ولا يُرسل إلى المتصفح.

## مسارات إدارة Opera

- `GET /api/admin/gitea/status`
- `POST /api/admin/projects/:id/repository` مع `{ "name": "repo-name" }`؛ الاسم اختياري ويُستخدم slug المشروع عند غيابه. ينشأ المستودع خاصًا.

## قاعدة Opera

قاعدة `opera_dev` الموجودة في هذه البيئة كانت بلا حسابات أو أدوار قبل هذا الإعداد؛ أُنشئ فيها حساب المالك فقط. لا تحتوي هذه الخطوة نسخة من بيانات قاعدة خارجية أو من Replit.

## الاستضافة

هذه النسخة تعمل داخل Sandbox مؤقتة، وليست استضافة تخزين دائمة. لا ترفع مستودعات مهمة قبل نقل قاعدة PostgreSQL ومجلد `/var/lib/opera/gitea/repositories` إلى خادم وقرص دائمين.
